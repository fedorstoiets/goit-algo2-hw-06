## Структура

```text
goit-algo2-hw-06/
├── task_1.py
├── task_2.py
├── README.md
└── .gitignore

Лог-файл lms-stage-access.log використовується локально
для тестування другого завдання, але не додається до репозиторію
через його великий розмір.
Завдання 1. Bloom Filter
Реалізовано клас BloomFilter для ефективної перевірки,
чи використовувався пароль раніше.
Фільтр Блума використовує компактний бітовий масив та декілька
хеш-функцій.
Паролі передаються до класу як звичайні рядки.
Хешування виконується лише внутрішньо як частина роботи Bloom Filter.
Основні методи
bloom.add(password)


додає пароль до фільтра.
bloom.contains(password)


перевіряє ймовірну наявність пароля.
Функція:
check_password_uniqueness(    bloom_filter,    passwords)


повертає статус кожного пароля:
- вже використаний
- унікальний
- некоректний пароль
Нові унікальні паролі також додаються до фільтра.
Особливість Bloom Filter
Bloom Filter може давати false positive:
елемент може бути визначений як наявний, хоча він не додавався.
False negative для правильно реалізованого Bloom Filter не виникає.
Завдання 2. HyperLogLog
Реалізовано порівняння двох методів підрахунку
унікальних IP-адрес:
1. точний підрахунок за допомогою set;
2. наближений підрахунок HyperLogLog.
Лог-файл обробляється построково, тому весь файл не потрібно
завантажувати у пам'ять.
Некоректні JSON-рядки, відсутні IP-адреси та некоректні
IP-адреси ігноруються.
Точний метод
exact_unique_count(file_path)


зберігає всі унікальні IP у set.
Пам'ять залежить від кількості унікальних IP:
O(n)

HyperLogLog
hyperloglog_unique_count(file_path)


використовує фіксовану кількість регістрів.
При p = 14:
m = 2^14 = 16384 registers

тому використання основної пам'яті HyperLogLog практично
не залежить від кількості унікальних елементів.
Запуск
Спочатку завантажте файл:
lms-stage-access.log

і покладіть його в директорію проєкту.
Потім:
python task_1.py
python task_2.py

Результати
Для наданого набору даних точний метод знаходить:
28 unique IP addresses

HyperLogLog дає дуже близьке наближене значення,
приблизно:
28.02

Фактичний час виконання залежить від комп'ютера.
Висновок
Точний підрахунок через set дає точний результат,
але використання пам'яті збільшується зі зростанням кількості
унікальних значень.
HyperLogLog повертає наближений результат із малою похибкою,
але використовує фіксований обсяг пам'яті.
Тому HyperLogLog особливо корисний для дуже великих потоків даних,
де точне зберігання всіх унікальних елементів потребувало б
значного обсягу пам'яті.
```
